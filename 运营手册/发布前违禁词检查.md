# 发布前违禁词检查

生效：2026-10-16。来源：用户要求“每个平台、每一条内容发布之前检查违禁词再发布”。硬规则见 `00-必读.md` 2.2.8。

## 检查范围与时机

全平台逐条执行：抖音示例作者、抖音 Office、视频号、小红书、微博、知乎回答/文章/想法、公众号文章/贴图、B站、快手。同一成片跨平台仍需分别检查平台版标题、简介和素材。云发布、网页发布、原生定时提交、到点发送及失败补发均适用。

在 humanizer-zh 定稿及素材完成后、提交平台前检查最终版本。覆盖标题、副标题、正文、简介、话题、封面/卡片/截图里的可读文字、字幕、旁白和计划首评。图片逐张看，视频结合完整字幕/口播稿和抽帧核对；音频识别与脚本不一致时先纠正，不能只查 post.json。素材读不到或文字核不清，不写“已通过”。

## 执行方法

1. 读取 `/path/to/workspace`，指定本次目标平台、内容类型和完整最终文本，按词表找候选风险并保留位置、原句、类别。
2. 结合上下文复核绝对化宣传、夸张效果/收益承诺、引流、诱导互动及平台相关表达；同时读对应 `平台打法/<平台>.md`。词表命中不是自动违规：例如“第一次使用”、有来源的实测成本比较、新闻中客观提到其他平台名称，要记录语境理由，不机械替换。不得声称社区词表是官方完整规则，也不得编造规则出处或限流结论。
3. 技能未单列微博/知乎/B站词库：这些平台使用通用检查，加本平台手册及当前可核实的平台规则；报告明确“无专用词库”。不把其他平台词表直接冒充这些平台规则。只有确实需要核实的边界项才查平台官方来源。
4. **发现风险用词直接改掉，复检通过后按原排期继续发布，不为常规改稿再问用户**。技能只负责检测；当前执行 Agent 根据风险改写，保持事实、数字、来源和限定条件。修改涉及图片则重出图片，涉及旁白/字幕则重出成片并按原流程重做声音质检。不用谐音、拼音、符号替代来绕检查。
5. 修改后对最终版本复检，逐平台写结论。确认误报的可保留但需原句与理由；仍无法判断的项标“待核实”，不能照搬技能中“不确定就低危”的默认处理。未查、漏查、未解决风险均不得发布；能自行改好就继续，不把常规改稿交回用户。
6. 改稿、改标题、换图、临时加话题或首评，复检受影响部分；复用之前记录须确认版本和素材完全一致。定时已经提交平台的先查编辑能力和状态，不重复提交；公开内容不因新增规则擅自删除重发。

## 记录（条目目录 review.md 内逐平台填写）

```text
### 发布前违禁词检查｜<平台/账号>
时间：<北京时间>
版本：<最终文本/素材文件及修改时间或 hash>
工具：content-compliance-checker（固定上游提交见调研）+ 平台手册 + 语境复核
范围：标题、正文/简介、话题、图片文字、字幕、口播、首评（不适用写明原因）
命中：<词句、位置、风险类别；无则写无候选命中>
处理：<改写前后；确认误报则写语境依据>
复检：<修改后结果、剩余待核实项>
结论：通过 / 待修改 / 待核实
```

检测通过只说明本轮未发现未处理的用词风险，不代表平台审核保证通过。现阶段这是 Agent 的强制执行检查点；ops.py 的 lint 仍是原有检查，尚未自动验证本记录，不应声称已经有全素材自动拦截。

## 存量未发布内容每轮补查

开工核对台账、当前批次计划和知乎回答独立记录，覆盖本地待发、待补发、平台草稿、未来日期课程及原生定时。旧失败已有替代、withdrawn、实际已公开的内容不重复发布。过去时段仍写 scheduled/success 的条目先核实公开状态，不能按“未发”重投。

有风险用词：直接改文本→涉及图片/旁白/字幕则重出→复检→同步实际平台定时/草稿→刷新回读→记录后按排期发。只改本地文件而没有保存平台编辑器，必须标“平台待同步”，不得报完成。无法编辑/访问时保留已有单，记录具体阻断，不取消重投、不新增扫码打扰。没有确认风险的内容写清语境复核理由，保持原排期。

## 知乎已定时回答的编辑副作用（10-16实测）

进入已定时回答的 #write 编辑页后，列表原定时标记可能消失，即便没有改正文或点击取消。优先在列表/预览读回，确需进入编辑器核查全文时，完成后必须核对并在同一原稿恢复原日期和时间，再确认定时发送；关闭编辑页后在草稿列表确认唯一条目和原排期。不要为了复查反复打开编辑器，不新建回答替代。工具可能短暂只显示旧DOM，操作后检查弹窗/列表的实际状态，不把单次超时当作操作未生效而重复提交。
