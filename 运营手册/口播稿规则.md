# 口播稿规则（v1，2026-10-16）

用户 10-16 反馈：视频 AI 感重、听不进去、内容单薄。这份规则管**视频的口播稿和画面编排**（make_motion 的 spec.json），每条视频写稿时对照。
依据：已安装的 hyperframes-creative / faceless-explainer / hyperframes-animation / media-use 几个 skill 的旁白、节奏、动效、音频文档（10-16 调研），human-writing skill 的口播写法，加上我们自己的去 AI 味规则。

**写稿流程**：先用 Skill 调 `human-writing`（它的 references/formats.md「口播、播客与演讲」一节：写给耳朵、新名词第一次说全、数字只留必须记住的、一口气说不完就拆开）起草或改稿 → 再过 `humanizer-zh` → lint（会顺带跑 human-writing 的 check_prose.py）。`lint_content.py` 会自动查其中能机器查的部分。

## 1. 字数和节奏

- **语速预算**：配音默认 rate +3%，按每秒约 5.5 个字估（换成本人声音后以 make_motion 打印的「开头体检」实测时长为准）（英文字母按半个字算）。60 秒 ≈ 280–300 字；2–4 分钟系列 ≈ 600–1200 字。稿子要感觉「比视频短」，宁可少一句。热点快评想更紧凑可以在 spec 写 `"rate": "+6%"`。
- **每个场景 1–3 句，每句 8–20 字**，一句只说一件事。长短句交替，别每句都一样长。超过 3 句就拆成两个场景，不然画面会冻住。
- 场景之间会自动留 0.35 秒换气。需要「屏息一拍」（揭晓结论前、反转前）在那个场景写 `"pause_after": 0.8`。
- 句子里想停顿用逗号；**不用破折号**（TTS 会读断）。
- 想刻意停一下（揭晓前、反转前），在句尾写 `[停0.6]`（秒），配音会在这里断开再接，字幕里不显示。一条视频用 1–3 次，多了像卡顿。

## 2. 开头 3 秒

- 第一句 ≤ 16 字、2 秒内念完（10-16 从 18 字收紧，make_motion 渲染前会体检），直接给冲突、反常识或后果。禁止「大家好」「今天聊聊」「最近 XX 很火」这类开头。
- 前 15 秒的结构（0–2 秒钩子 / 2–5 秒确认 / 5–15 秒兑现第一条干货）见 `批次执行.md` 2.4 节。
- 钩子类型轮换着用（spec 里写 `"hook_type"`，同一账号连续两条不重复）：
  反常识 / 痛点认同 / 点名受众（「用 XX 的注意了」）/ 后果代价 / 带利害的数字 / 想象场景 / 悬念提问 / 对比反差 / 亲测翻车（必须有实测记录）。
- 数字只有带利害才放开头：「补偿只给一种人」可以，「改了 23 处」不行。
- **核心结论最迟第 2 句说出来**，后面都是证据和展开。

## 3. 结构

- 整条只选一种结构：**概念**（是什么→为什么→跟你有什么关系）/ **流程**（第 1 步…第 N 步）/ **清单**（3 条最有力，别凑 5 条）/ **故事**（起因→转折→结果）。
- 不按新闻稿段落顺序复述。原文是信息来源，不是脚本：重排、合并、删。
- 2 分钟以上的系列：每 20–30 秒给一个新的小钩子（「但这里有个坑」「真正贵的是后面这个」），用 chapter 场景分段。
- **背景后置要补回接句**（10-16，xy-script-glue 诊断）：挪到 15 秒以后的背景段，第一句说明为什么现在讲它（例：「这个判断，是拿六周零收入换来的。」）；时间不要倒着走，日期第一次出现时带月份。

## 4. 说人话


- 书面词换成口语：

| 别写 | 改成 |
|---|---|
| 据悉 / 据报道 / 援引 | 有媒体说 / 报道说 |
| 表示 / 称 | 说 |
| 进行测试 / 进行了升级 | 测了一下 / 升级了 |
| 该产品 / 此次 | 这个产品 / 这次 |
| 此外 / 与此同时 | 还有 / 同时 |
| 值得注意的是 / 需要指出的是 | （直接说那件事） |
| 综上所述 / 总的来说 | （删掉，直接给结论） |
| 首先、其次、最后 | 第一、第二；或者干脆不编号 |

- 口语转折（「但问题是」「你想想」）每条最多用 2 次，多了像套路。「说白了」「说穿了」「先说结论」是 human-writing 的硬禁词，不用。
- 不用冒号和破折号（TTS 停顿生硬，human-writing 也禁），「不是……而是……」这类翻案句不用。
- 不编经历：没有实测记录不说「我试了」「我发现」，改成「官方说」「有人测了」。

## 5. 数字和专有名词

- **口播取整，画面给精确值**：口播「快 5 个小时」，画面 timeline 写「4小时53分」。
- 写成 TTS 好念的样子：「135+」写「一百三十多」；生僻英文缩写第一次出现时先合成听一遍，读错就改写法。
- 日期别写「今天」「昨天」，写「10月15号」或「周三」（视频可能隔天才发，B 站、视频号会复用）。

## 6. 结尾

- 一句话收束全片，最好回扣开头那个冲突。
- 最后一句是**具体问题**：「你现在主力用哪家，备用的是哪家？」可以；「你怎么看？」不行。
- cta 场景最多 2 句，别在结尾拖。
- **最后一个 cta 场景自动套统一片尾模板**（10-16，`scripts/edit_fx.py`）：上面问题大字（cta 的 `text`）→ 左下角的示例作者走到中间 →「示例聊AI」落定 + 固定声音 logo → 人设一行 → 黄色胶囊。胶囊内容：场景写 `"next": "拿它做一份真报价单"` 显示「下集｜…」；没有 next 但顶层有 `series` 显示「合集 · 第N集」；都没有显示「每天一个能用上的AI」。
  - 片尾两句口播的写法（任选一种）：系列版「这是示例作者先试第 3 集，下集我拿它做一份真报价单。你现在写报价，最卡的是哪一步？」；带走版「提示词就在这一屏，截图就能用。你打算先拿它干哪件活？」；热点版「这事有新进展我接着更。你们公司现在让用它写东西吗？」
  - **引导关注**：片尾画面有「＋关注 → ✓已关注」的点按动画；口播里要有一句**带理由**的关注引导，cta 没写的话 make_motion 会自动在片尾第一句补「关注示例作者，每天一个能直接用上的AI。」（Office 号补「关注我，AI工作台 每一课都会接着讲。」）。也可以自己写更具体的理由，比如「想看下集实测，点个关注就不会刷丢」。问题仍放最后一句。
  - 只引导关注这一个动作：不说「点赞」「一键三连」「评论区扣 1」，不放二维码、微信号、外链（诱导互动/引流红线）。

## 7. 画面跟着口播走

- 画面元素按句子出现：list / bars / timeline 的条目数 = 句数，或 = 句数 − 1（第一句是引子），make_motion 会让第 k 条跟着第 k 句出来。对不上时用 `"reveal": [0,1,1,2]` 指定第几条跟第几句。
- compare：第一句说左边，第二句说右边。
- 相邻两个场景不要同一类型；全片 ≥ 5 种类型（批次执行.md 原规则）。
- **每条至少 1 个真实素材场景**（screen）：官方公告截图、产品界面、实测截图。能拿到就用，比 AI 插图可信得多。没有就写进 review.md。
- AI 插图（image）短视频 ≤ 2 个，系列 ≤ 4 个（原规则）。

## 8. 声音

- 配乐：spec 写 `"bgm"`：放松（默认，热点/算账/抄作业）/ 欢快（先试、新品）/ 悬疑（事故、安全）/ 震撼（大事件）/ 大气 / 幽默；不想要配乐写 `"none"`。曲子从示例服务配乐库自动挑，最近 12 首不重复，配音出现时自动压低。
- 音效只在关键拍响（换场、数字落定、清单逐条、印章），不用每个场景都响。某个场景不要换场音效写 `"sfx": false`。

## 9. 交付前

1. 稿子过 humanizer-zh（口播稿也算「文字定稿」），review.md 里写改了什么。
2. `ops.py add` 会跑 lint，口播相关的检查项：场景句数、句长、书面词、开头长度、结尾提问、字数和时长估算。
3. 渲染后看 sheet / 抽帧，确认没有一个画面静止超过 4 秒。
4. hook 过一遍 `xy-opener`；2 分钟以上的稿子过 `xy-script-glue`，🔴 清零（调用方式见 `技能地图.md` 第 2 节）。
