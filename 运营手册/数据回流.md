# 数据回流与复盘

本流程只描述数据结构与判断方法，不携带维护者的真实账号表现、粉丝基线或运营台账。自己的作品快照保存在本地 state/、days/、reports/，不要提交到公开仓库。

## 采集与记录

1. 用各平台创作者中心或已授权接口核对自己的作品。scripts/collectors/ 提供浏览器采集适配源码，使用前核对当前页面与字段。
2. 保留平台、自己的账号标识、作品ID、公开链接、发布时间、采集时间、统计窗口与数据来源。不要跨平台混用指标定义。
3. 缺失字段记为缺失，不补成0；阅读/播放、展示与人数分开，24小时和72小时分开。多次快照用于观察变化，不覆盖原始证据。
4. 使用 metrics.py ingest 的平台适配器导入；确切命令与JSON结构见脚本。示例账号用 demo-*，生产账号只写在自己的私有配置中。
5. 粉丝数与粉丝历史按 dashboard/README.md 约定保存，让看板计算净增与趋势。

## 发布状态与数据质量

台账的定时中、提交成功、审核中、实际公开分别记录。没有公开回读证据，不为了凑完成率标 public。作品删除、隐藏、审核或链接不可访问时，保留观察时间与来源，不自行猜测限流原因。

采集错误、登录失效或字段变化只影响对应数据源；保留缺失状态，不把错误写成表现为零。发布通道异常不意味着作品一定没发出，补发前核对重复。

## 每日与每周

每天用 daily_report.py / evolve.py 汇总平台、栏目、形式、时段和实验组。每周比较相同窗口与口径，记录样本数、异常值和证据。只有样本足够且差异持续时才修改策略；样本不足则继续观察或设计单变量实验。

可比较阅读/播放、完播、收藏、评论与关注转化，但不把跨平台数值直接当同一指标。将结论写入自己的运营计划，再同步提炼后的公开方法；不要把真实业绩表导出为“示例”。

## X

X 的字段与接入要求见 [平台参考](平台打法/X.md)。通过自己可用的官方页面/授权通道采集，展示量与人数分开记录；缺字段不补零。新增采集适配器前先确认实际返回结构，不假设其他平台的指标一一对应。
