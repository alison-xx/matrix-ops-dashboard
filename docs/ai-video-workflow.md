# 内容驱动的AI视频制作

先确定观众要理解什么，再决定是否生成镜头。真实操作、输入输出与错误记录支撑实测结论；AI画面用于表达难以拍摄的概念、情景或转折。技术试片通过后仍只是素材，不自动成为运营内容。选题与复盘见[内容体系与节奏](content-cadence.md)。

## 从脚本到镜头

在分镜表中逐行写下口播、表达目的、素材类型、主体动作、景别、时长和衔接。没有独立表达任务的镜头删掉，不先批量生成办公室空镜再寻找选题。

- 实测或教程以真实录屏和交付物为主。AI可以解释抽象过程，不能生成软件界面、数据表或产品效果充当实测证据。
- 情景复演明确标注性质；生成的办公场景不能冒充真实公司现场。
- 纯AI创意短片可用完整生成画面，但仍需叙事、镜头衔接与声音验收。跨镜头固定角色、道具数量、光向和运动方向。
- 画幅按目标平台独立设计。720P素材即使进入1080P剪辑工程，也不能称为原生1080P。

每镜头集中表达一个连续动作。构图预留字幕位置，人物和道具不能挡字。生成原声默认移除，由统一配音、配乐和字幕轨完成剪辑。

## 当前适配器与配置

本节描述仓库的接口适配约定，不承诺供应商接口、价格或免费活动长期不变。实际调用前核对[Agnes公开文档](https://www.agnes-ai.cn/zh-Hans/docs/agnes-video-25-flash)与[Duomi公开文档](https://duomiapi.com/doc/98)。凭据放入使用者自己的环境变量或未纳入版本控制的 `config/.env`，限制本地文件权限，不写进镜头、日志或分享材料。

|用途|配置与请求|
|---|---|
|首选文生视频|`AGNES_API_KEY`；模型 `agnes-video-2.5-flash`；POST `/v1/videos`；`mode=text`、`size=720P`、`seconds` 为4至12整数|
|查询首选任务|保留 `video_id`，通过 `/agnesapi` 传入任务ID和模型名|
|明确失败后的备选|`DUOMI_API_KEY`；模型 `veo3.1-fast`；POST `/v1/videos/generations`；`quality=1080p`|
|查询备选任务|GET `/v1/videos/tasks/{id}`|
|本地成本预留|`AI_VIDEO_DAILY_CAP_CNY`；先核脚本默认值与剩余预算，再设置适合自己的上限|

当前CLI只适配文生视频。参考图、首尾帧需要有明确实现后才能使用，不能静默丢弃输入后继续生成。供应商返回的实际时长、分辨率应通过媒体探针核对；不同模型的参数不能直接互套。

示例镜头只演示结构，不含私人素材或既有作品信息。

```json
{
  "subject": "一张无字纸卡与一只木托盘，室内桌面",
  "action": "纸卡从桌面左侧缓慢滑入托盘并停住，保持一个连续动作",
  "camera": "俯拍固定机位，不推拉，不切镜",
  "lighting": "左侧自然柔光，低饱和灰蓝配色",
  "composition": "托盘在画面上半部，下半部留字幕安全区",
  "continuity": "始终一张纸卡、一个木托盘，材质与光向不变",
  "seconds": 6,
  "aspect_ratio": "9:16"
}
```

```sh
.venv/bin/python scripts/ai_video.py work/shot-01.json --dry-run
.venv/bin/python scripts/ai_video.py work/shot-01.json
.venv/bin/python scripts/ai_video.py work/shot-01.json --poll
```

先自行创建工作目录与镜头文件。`--dry-run` 只验证请求构造；提交、下载、审核和公开是不同阶段。输出为同名 `.job.json` 和成功下载后的 `.mp4`。每次 `--poll` 查询一轮，可间隔15至30秒续查；长时间未完成时记录待回收，下一轮沿用原任务ID。

## 防止重复提交

|观察到的结果|下一步|
|---|---|
|返回可查询ID，仍在排队或执行|保存原ID继续查询，不因等待而双投|
|明确拒绝或生成终态失败|按适配器规则最多回退一次，保留两次尝试|
|POST超时、服务器异常或无可查ID|标记 `uncertain`，先向供应商核实，禁止自动重投|
|查询接口报错|保留原ID重查；查询失败不能推断生成失败|
|任务完成但下载失败|重新取得原任务结果，不重新生成|
|提示词修改|另存新版本镜头文件，保留原任务，不删除旧记录伪装新任务|

两家都明确失败后，记录阻断，改用真实素材或重新设计。若服务明确拒绝访问，应停止相关操作，不更换通道绕过限制。

成本控制以原子预留防止并发超支。预留金额属于保守估算，不能冒充供应商账单；失败预留也不应在未核对前自动释放。公开使用者应检查实际适配器费率与限额，按自己的预算配置，不继承任何私有运营额度。

## 素材与成片验收

先看完整运动，再核首、中、尾帧。检查主体数量、手部和形变、闪烁、异常文字、水印、运动逻辑及同组一致性。可按内容相关、运动自然、构图、材质光线、一致性分别计0至2分；总分至少8且没有严重缺陷，才进入剪辑。分数不能替代具体观察。

审核人实际看过后，在同名 `.review.json` 写视频实际 `sha256`、`approved: true`、评分和发现的问题。没有看过不能签核。素材改动后哈希变化，需要重新检查。

在 `make_motion.py` 的 `type=video` 场景里设置本地 `video` 路径、`source_kind=ai`、`trim_start`、`headline`、`lines`；真实视频标 `source_kind=real`。时长不得超过素材剩余长度，不通过循环或冻结尾帧凑时长。调用前核对当前脚本支持的结构。

成片执行 `audio_qc.py`，核对旁白、字幕、配乐和音效，再查看封面、抽帧及完整播放。合格后进入[外部内容交接](external-content-handoff.md)或使用者自己的发布流程。下载成功与本地检查通过均不等于平台已公开。

## 复盘留下什么

每条记录镜头目的、供应商与模型、原始分辨率、生成与采用数量、弃用原因、回退原因、预留金额和实际费用是否核对。下一轮只针对一个可观察缺口改法，例如减少同镜头动作，观察形变是否下降。

内容反馈需要另外取数。画面更精致不能直接证明留存、分享或关注增长；保留未满观察周期、小样本和缺失字段的限制。公开分享只保留可复用方法、示例和代码，真实任务ID、账单、账号与个人素材留在自己的私有工作区。
