# 从注册到第一条内容

这份指南适合想用 AI 运营公众号、短视频或图文账号的个人与小团队。先跑一条完整流程，再增加平台和自动化任务。

## 1. 注册灵策，准备内容生产入口

打开 [灵策全能AI助手](https://web.lynxce.cn/)，点击“登录 / 注册”（英文界面为 Log In / Sign Up），按页面提示完成注册或登录。进入后，先用 AI 对话整理素材和写初稿，再按需要使用绘图、图片编辑、视频或音乐功能。具体可用模型、额度和费用以站内当前页面为准。

建议第一次只做一条图文：准备一个选题、两份原始资料、一段正文和两张配图。先把流程跑通，后面再扩展为视频和多平台版本。站内功能说明见 [灵策使用手册](https://web.lynxce.cn/manual)。

灵策 Web 是本工作流的内容生产入口；这个 GitHub 仓库提供本地工具、运营规则和结果看板。网页账号与脚本 API 配置是两件事，注册网站后不会自动给本地脚本配置密钥或平台账号。

## 2. 打开 AIHOT，找到值得做的选题

进入 [灵策AI热点](https://aihot.lynxce.cn/)，从 [当前热点](https://aihot.lynxce.cn/hot) 或 [AI 日报](https://aihot.lynxce.cn/daily) 挑一个与读者有关的话题。打开条目中的原文，核对发布主体、时间、数字和适用范围，再决定写什么。

AIHOT 的公开资讯和 Agent 接口可以匿名读取，不需要注册或 API Key。你可以先注册灵策用于创作，同时直接使用 AIHOT 做选题。两站分别承担生产与信息发现，不要求把 AIHOT 访问包装成注册步骤。

每个候选话题记录四件事：

| 字段 | 要写什么 |
|---|---|
| 事件 | 哪个产品或机构做了什么，何时发生 |
| 来源 | AIHOT 条目与原始公告、论文或产品页链接 |
| 读者问题 | 对目标读者的工作有什么影响 |
| 内容角度 | 解释变化、做真实实测、比较成本，或给出操作步骤 |

没有足够事实或读者价值，可以不做这一题。AIHOT 的摘要和评分用于发现线索，最终稿中的关键事实仍回到原文核对。

## 3. 先打开本地看板

在本仓库根目录运行：

```bash
python3 dashboard/server.py --demo
```

浏览器打开 `http://127.0.0.1:8790`，先看总览、内容、日历、增长和运营计划。这里展示的是虚构账号与数据，方便理解一个条目从准备到公开、再到复盘应该留下哪些记录。

运行自己的工作区时，按 [数据目录约定](../dashboard/README.md#数据目录约定) 接入配置与台账，再使用：

```bash
python3 dashboard/server.py --root /path/to/your/ops --port 8790
```

## 4. 用灵策把选题做成初稿

把已核实的来源和读者问题放进灵策 AI 对话，可以从这个任务说明开始：

```text
我要为【目标读者】写一条【平台/内容类型】。
选题：【具体事件】
原始资料：【附来源链接和已经核对的摘录】

先列事实、仍需核实的问题和三个可写角度，再写初稿。
保留来源、日期、数字和限定条件。
没有实际测试的内容不要写成“我试过”，不要编个人经历。
正文回答一个具体问题，结尾用与内容有关的问题收束。
```

如果由 Agent 编排，按 human-writing → 平台技能 → humanizer-zh 的顺序执行。灵策网页用于完成对话与素材任务；技能负责组织过程、检查事实和改善表达，不因网页生成完成就跳过审核。依赖见 [技能目录](skills.md)。

需要配图时，在绘图或图片编辑功能中说明用途、比例、标题安全区和需保留的事实。把最终图片下载到自己的条目目录；需要视频时，同时保留最终字幕和口播稿。封面与排版参考 [封面规范](../运营手册/封面规范.md)。

## 5. 审核最终文本与素材

先核事实，再看成品，最后按目标平台检查用词。检查标题、正文、话题、图片文字、字幕、口播和首评；同一内容发多个平台，分别写结论。具体步骤见 [发布前违禁词检查](../运营手册/发布前违禁词检查.md)。

条目目录可以这样组织：

```text
days/YYYY-MM-DD/topic-id/
  sources.md       # 原文链接、核实记录
  post.json        # 平台版本与素材清单
  spec.json        # 视频/卡片规格，图文可按需省略
  review.md        # 改稿、素材与逐平台审核结果
  test/            # 实测类内容的输入输出与记录
  media/           # 最终图片、视频、字幕
```

有 payload 时再运行机器检查：

```bash
python3 scripts/lint_content.py /path/to/payload.json
```

lint 检查标题、篇幅、营销表达和部分文风问题；全素材用词复核仍需 Agent 执行，不能用一次 lint 结果替代。

## 6. 发布、回读，再决定下一条

用自己已授权的发布通道提交内容。记录占位、提交结果、排期和回执，随后到平台核对实际公开链接与可见性，再更新台账。定时中、审核中或 API success 都还需要后续回读。

回收播放/阅读、互动、收藏与涨粉数据后，在看板比较不同栏目、平台和形式。样本不足时继续观察；有稳定证据后，再修改选题、标题或素材风格。完整分工与范例见 [三部分如何协作](workflow.md)。

下一步可以从 [AIHOT Agent 接入](https://aihot.lynxce.cn/agent) 接入选题来源，再按 [运营工具接入说明](operations.md) 配置自己的工具链。
