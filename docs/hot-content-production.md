# 从当天AI热点到原创内容

把实时信息变成观众愿意看完的解释：采集 → 核实与拆解 → 原创标题 → 开场钩子 → 信息推进 → 兑现。热点与日常连载可以穿插；品牌只有在真实任务与事件相关时进入故事。

## 事件卡

分别保存事件发生时间、原文发布时间、抓取时间与时区；保存原始来源、读取范围、热度证据、受众、已确认事实、未确认部分、编辑推断和去重ID。今天抓到的旧新闻不等于今天刚发生。作者新作也不自动等于全网热点。

发现工具与创作者内容只提供线索。事实回到公告、论文、产品或实际测试；不把别人的经历、测试结果和文字变成自己的亲历。没有合格新事件时记录空缺，不为了频率编造变化。

## 拆解与包装

先回答：发生了什么？谁会遇到它？哪一步容易误解？看完能做出什么判断或动作？选一个主要问题，不逐项朗读功能表。

每题写至少五个有材料支撑的标题方向，以及至少三种开头：可见结果、具体问题、真实反差。标题负责选题和点击，封面突出一个变化，开头立即呈现问题。三者互补。结论也可以前置，再用条件、方法或例外留下继续看的理由。

不以“看到最后”“颠覆认知”替代信息，不以修改同义词复刻同行文案，不承诺正文没有的实测或效果。

## 持续给出新信息

短稿可从这个节奏起步，按实际时长调整，不当成算法定律：

| 位置 | 必须给出的信息 |
|---|---|
| 开场 | 可看见的结果或问题，以及受众的理由 |
| 紧接开场 | 本条查什么，出现第一份证据 |
| 前段 | 先兑现一部分，给出能照做的一步 |
| 中段 | 新条件、偏差或分支改变刚才的判断 |
| 结尾前 | 回答开头问题，交付完整判断/清单/产物 |
| 最后 | 一个具体讨论问题，或有真实安排的下一步 |

每段标注“观众新知道了什么”。没有新信息就删。抽象解释换成可读画面或具体输入输出；开着的问题不要越积越多。笑点来自真实反差和取舍，假设演绎应明确标示。音效和切镜服务于信息。

## 平台适配

短视频先给可见问题与变化；业务场景视频讲任务、偏差和取舍；实操视频让动作连着结果；长视频保留关键分支与复现；图文前两页就给第一步；长文章展开选择、条件与代价；问答先正面答题；短帖给一个变化和可检查的结果。共用事实，分别组织主要问题、证据、顺序与交付物。

## 审稿记录与验证

每条记录 `news_event_id`、`timeliness`、`source_urls`、`known_unknown_inference`、`viewer_question`、`viewer_payoff`、`title_candidates`、`selected_title_reason`、`hook_candidates`、`selected_hook_reason`、`retention_beats`、`first_payoff_time`、`originality_and_platform_delta`、`publish_hypothesis`。

按实际成片核对首次回报、开头承诺兑现、字幕、配音、封面与来源。音视频改版使用可区分的上传资源，避免旧路径缓存误用旧素材。

发布后取可取得的24小时数据，优先比较本账号同题型、时长和时段。没取得的字段明确留空，一次结果只形成低置信假设。不同平台、不同题材的作品不是严格A/B实验；不要在同平台重复发布同题测钩子。

素材完成、交接、原生定时、公开可见、产生业务效果分别登记；定时接口中间回执仍须核对平台实际生效。
