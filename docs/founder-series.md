# 把公司实践做成跨平台长期系列

用开发、产品、协作、成本、运营与日常作为长期素材线。每集围绕一个具体问题，留下可检查的结果；系列可以记录尚未解决的工作，不必每期宣布成功。栏目名、人物设定和场景可设计，真实记录、计划、流程复演和虚构短剧要能分辨。

## 建一份事实母档

记录母题ID、原始材料、发生时间、已经完成与尚未确认的部分、允许公开的范围。代码通过测试、内容事实正确、作品已发布、产生业务效果是不同状态，分别保留证据。不要从测试数量推导人效，也不要把别人的实测和经历当成自己的经营记录。

选题储备只说明有方向。进入制作前仍要补材料、去重、检查已提交与预排内容，沿用原选题库和发布台账。编号在实际制作/交付流程里登记，不能按设想提前宣布连载成果。

## 按平台重新取材

| 平台类型 | 核心问题 | 适合的独有产物 |
|---|---|---|
| 公众号/长文 | 为什么作这个选择，代价是什么 | 完整决策过程和成立条件 |
| 短视频 | 眼前哪一步出了变化 | 一个冲突、一个结果和动作 |
| 业务负责人视频 | 工作怎样算交付，谁处理异常 | 责任分工与验收标准 |
| 图文笔记 | 怎样照着做 | 清单、表格、步骤与限制 |
| 长视频 | 过程怎样复现，不同路线怎么选 | 实际演示、分支与失败修正 |
| 微博/短帖 | 今天改了哪件事 | 一项决定和依据 |
| 问答 | 对这个实际问题有什么解释 | 成立条件、反例、适用范围 |
| 日常实操 | 今天拿工具做了什么 | 朴素动作与可见结果 |
| 办公课程 | 学完能交出什么 | 示例输入、产物和验收练习 |

可以共用事实与原始素材，脚本、论证次序、核心案例或解释深度与最终产物要为平台重做。只换标题、封面和简介不算改编。无需同一天把同一母题铺满所有平台。每条review记录平台独有问题、证据与交付物，人工对照正文。

## 接入已有运营

先以少量原有发布位穿插连载，保留热点、实测和常规教程。排期、预算、身份、视觉、声音、人工交付边界与既有实验仍执行各自规则。平台已经采用不同稿件时，不再把跨平台效果差异当成同一成片的分发差异。

创作者的新作只负责发现值得处理的问题。阅读全文或字幕，核一手事实，再用自身材料重建。研究方法见[创作者研究](creator-research.md)。采集到线索、形成选题、写成文稿、完成制作和取得公开链接逐级登记。

发布后使用本号实际数据验证结构假设，在相近题型与受众中比较；样本不足就保留为假设。公开流程时，只同步通用方法与虚构示例，真实经营材料、个人账号、待发稿与他人正文保留私有。

## 把过程讲成故事

同时按[当日热点内容生产](hot-content-production.md)执行：具体任务→阻力→选择→结果→下一步。先给可见问题，不用公司愿景做长铺垫。热点只有与本号真实开发或经营任务相关时才接入连载。开头承诺要在正文兑现，中段每段有新信息，趣味来自现场反差，不编造经营经历。
