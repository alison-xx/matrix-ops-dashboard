# 内容体系、生产节奏与每日学习

先定义关注者持续能得到什么，再安排数量与时间。可将主线分为真实任务实测、项目中的选择、重要能力变化，以及观众问题与复盘。栏目比例是选题结构目标，不是把同一脚本铺满平台的配额。

本文件提供通用方法，不包含任何运营者的账号、实际排期、授权或生产台账。使用者需要结合自己的容量与数据制定日历。

## 按平台交付不同价值

|形式|读者或观众带走什么|成品要求|
|---|---|---|
|短视频|一个问题怎样被解决|具体冲突、过程与结果；复杂问题按讲清所需时长制作|
|办公场景视频|哪一步能交给工具、怎样接手|实际情景、可用条件与责任边界|
|长视频|完整能力与限制|真实输入输出、关键步骤、边界例与复现条件|
|搜索型图文|可保存、可照做的方法|一个具体任务，完整步骤或检查表，逐页提供新信息|
|问答|对一个真实问题的充分回答|先回答，再论证；证据范围与问题适配|
|长文章|可反复查阅的流程或判断|案例、依据、操作步骤和限制，不用内部流水充篇幅|
|原生短文|简洁的工作发现|一个具体事实或方法，有必要才展开小线程|

先围绕一个有证据的核心任务做内容，再选择哪些平台存在独立价值。共用事实与素材，但重新确定开头、证据顺序、表达长度和交付物。只换标题或截短同一成片，不能算完整适配。没有合格选题时记录空缺，不拿旧闻补数量。

固定节奏先稳定一段可观察周期。发布时间是待验证安排，不能套用其他平台的“黄金时段”。样本不足时修明确错字、事实错误和音画缺陷，不凭一条结果改全盘频率。

## 从候选到成品

依次完成观众问题、来源与实测、交付目标、标题与开头候选、完整脚本、分镜、素材、平台版本、审核、交接、公开证据与反馈。每一阶段有自己的状态。

- 候选只有题目或阅读线索时，列为未来候选，不能登记成已排未发布成品。
- 实测类先保存输入、原始输出、环境、命令与错误，再写结论。没测过的性能或使用效果留空，不用概念画面补成“验证”。
- 脚本通过后仍需配音、画面与成片验收。完整文字、视频成片和平台定时分别登记。
- 标题承诺指向正文证据，`review.md` 写清给谁看、为什么现在看、开头承诺、中段新增信息、最终交付，以及与近期作品的区别。

中文创作用 human-writing 起草，再用 humanizer-zh 核对表达与事实边界。相关技能见[技能清单](skills.md)；AI镜头按[AI视频工作流](ai-video-workflow.md)设计。项目评测的证据与复现要求见[GitHub实测流程](github-review-workflow.md)。

## 每天学习与应用

学习任务接入已有生产班次，不为同一个职责另开重复调度。一天围绕一个具体质量缺口学习，避免堆积链接。

1. 开工时读上一轮复盘，提出一个问题。实读一份平台原始说明或可信创作者的完整方法，记录发布日期、实际阅读范围与适用限制。只有标题就写只有标题，不称读过全文或看过视频。
2. 制作时把一个方法落实到一条尚未公开的内容，保存改前、改后及改动目的。一天只试一个主要变量，避免同时改标题、时段、长度后无法解释结果。
3. 交付前检查是否兑现学习假设。记录实际修改与未解决问题，不以“已学习”代替成品变化。
4. 在固定观察窗口回读数据，注明采样时间和内容年龄。可以使用24小时、72小时快照，但没有完整观察周期时不能提前下结论。
5. 下一轮决定保留、停止或待证。没有新材料时可深入旧资料，不以来源数量计学习成绩。

建议记录以下字段。

|字段|要写清的内容|
|---|---|
|问题与来源|当前缺口、来源链接、发布日期、阅读范围|
|方法与限制|原方法说了什么，哪些条件与本账号不同|
|实际修改|原内容位置、改后内容、为何这样改|
|验证|主要变量、观察指标、采样时间与样本数|
|结果|已观察到什么、缺什么、保留或停止的依据|
|下一步|复查时间和具体动作|

## 周复盘与数据口径

按平台、栏目与内容长度比较相近样本，不把不同受众和形式混算。至少积累多条可比且完成观察周期的内容，再讨论长期结构调整；样本门槛由使用者提前确定。优先看样本数、中位数与分布，保留缺失字段，不补成零。

短视频可看开头流失、平均观看与关注；图文可看收藏和搜索入口；长内容可看读完、有效评论、分享与复查用途。指标是否可取得以平台实际开放为准，不编造后台没有提供的字段。

每周只做少量长期调整，并保留理由、起始版本和复查时间。外部创作者的方法是可尝试假设，只有本号证据支持后才能称为已验证。画面变漂亮、脚本变短或产量提高，也不能直接推成增长效果。

## 未发布内容迁移

调整体系时先盘点原记录，按同一内容ID追踪制作进展，不再造一份相互冲突的发布台账。

|原状态|处理|
|---|---|
|已公开且有证据|排除，不重复发布|
|旧定时日期已过、结果未知|先查平台与原任务；不能因本地无链接推断没发|
|本地草稿或成品，尚未提交|保留原版，重写或重剪，通过检查后再进入待发队列|
|已提交且确认未公开|先做本地新版，再核平台能否原位替换|
|不能原位替换|必须先有取消成功证据，再考虑新提交|
|外部执行者已领取|交新版本、差异和原ID，不静默覆盖对方已领取材料|
|过期、违规或同题已公开|停止补发并说明原因，不换标题规避原问题|
|只有选题或未经验证的设想|留未来候选，先补证据，不当已排成品|

本地改稿标记 `replacement_pending`，直至平台替换得到确认。原任务结果不明时保留 `uncertain`，不删除状态重投。材料交付、平台提交、原生定时、公开可见分别保存证据；`success` 字样本身不代表公开。

迁移检查表只存制作版本与差异。生产账号、原单ID、凭据、真实账单和私人媒体留在使用者的私有目录；公开同步只带可复用流程、示例与脱敏代码。隐私边界见[隐私说明](privacy.md)。
